# 개발 로드맵

이 문서는 실제 주문을 안전하게 도입하기 전까지의 개발 순서와 각 단계의 완료 기준을 정의한다.

## 1단계: DCA DRY_RUN 실행 흐름 — 완료 ✅

목표는 활성 DCA 전략을 KST 일정에 따라 평가하고, 실제 주문 없이 플랫폼별 주문 요청을 생성·기록하는 것이다.

- [x] DCA의 매일·매주·매월 실행 일정 지원
- [x] 매주 실행은 요일, 매월 실행은 1~28일을 전략 설정에 저장
- [x] 실행마다 전략 실행 이력과 생성 주문을 SQLite에 저장
- [x] 같은 전략이 같은 예정 시각에 두 번 실행되지 않도록 보장
- [x] 앱 내부 스케줄러와 수동 DRY_RUN 테스트 실행 제공
- [x] 실제 주문 전송을 하지 않는 DRY_RUN 모드 유지

완료 기준: 실행 이력 화면에서 실행 시각, 전략명, 상태, 생성된 DRY_RUN 주문을 확인할 수 있어야 한다. **충족**

제한 사항: 앱이 중지된 동안 지나간 실행 시각은 보정 실행하지 않는다.

## 2단계: DRY_RUN 거래 비용 추정 — 완료 ✅

- [x] 전략별 수수료·세금·슬리피지 가정 입력 및 검증
- [x] 금액 주문의 예상 원금·비용·총 소요액 계산
- [x] 수량 주문은 최근 동기화 현재가를 기준으로 계산
- [x] 계산 근거가 없는 수량 주문은 비용 미산출 상태로 명시
- [x] 비용 추정 결과를 주문 이력과 화면에 저장·표시

완료 기준: DRY_RUN 주문에서 사용자가 입력한 비용 가정에 따른 예상 비용을 확인할 수 있어야 한다. **충족**

제한 사항: 입력한 비용률은 사용자 가정이며, 실제 주문 시점의 증권사 요율·세금·체결 가격을 보장하지 않는다.

## 3단계: 주문 전 리스크 검증 — 미완료 ⏳

- [ ] 플랫폼별 주문 가능 현금·최소 주문 금액·거래 시간 확인
- [ ] 종목별 주문 가능 여부 및 업비트 주문 가능 정보 사전 조회
- [ ] 전략별·일별 예산 한도와 최대 주문 횟수
- [ ] 중복 주문 방지용 멱등성 키와 취소 정책

완료 기준: 검증에 실패한 주문은 외부 주문 API를 호출하지 않고 실패 사유를 실행 이력에 남긴다.

## 4단계: 운영 안정성 — 미완료 ⏳

- [ ] 외부 API 재시도, 백오프, 호출 제한 대응
- [ ] 플랫폼별 동기화·주문 실행 잠금과 장애 알림
- [ ] SQLite 백업·복구 및 스키마 마이그레이션 절차
- [ ] HTTP API 통합 테스트와 외부 API mock 테스트 확대

완료 기준: 재시작·외부 API 일시 장애·중복 요청 상황에서 자산과 주문 이력이 일관되게 보존된다.

## 5단계: 접근 보안과 배포 — 미완료 ⏳

- [ ] 대시보드 인증 및 권한 분리
- [ ] HTTPS 리버스 프록시와 외부 접근 제어
- [ ] 비밀값 관리 방식 정리 및 `.env.example` 제공
- [ ] 운영 로그·상태 점검·백업 자동화

완료 기준: 인증되지 않은 사용자가 전략 수정, 동기화, 실행 API를 호출할 수 없다.

## 6단계: 제한된 실주문 전환 — 미완료 ⏳

- [ ] 플랫폼별 주문 어댑터를 별도 승인 플래그 아래 구현
- [ ] 소액·단일 플랫폼·명시적 운영 승인 범위에서만 활성화
- [ ] 주문 접수 결과·체결·취소 상태 동기화
- [ ] 비상 중지와 전체 전략 일괄 중지 제공

완료 기준: 실주문 여부가 명시적으로 통제되고, 모든 주문의 요청·응답·상태 전이를 추적할 수 있다.
